## Metadata v1

Callers supply a bounded array of explicit mappings. There is no production registry in this batch. `ruleVersionMetadataErrors(record)` checks shape and known status values, not the truth of a source claim, approval of inherited content or behavioral correctness. A record has these separate fields:

| Field | Contract |
| --- | --- |
| `schemaVersion` | `1`; unknown schema versions are unresolved. |
| `documentUuid` | Exact typed or legacy compendium Item UUID, world Item UUID or owned Actor Item UUID. Never a display name, slug or catalog coordinate. UUID spellings are not normalized or guessed. |
| `type` | `move`, `ability`, `feat`, `edge` or `pokeedge`; must match the selected record. |
| `version` | `{id, label, kind}` with explicit nonempty ID/label and `original`, `revised` or `addition` kind. A revision-only addition has no invented original. Version tokens may be shared by distinct canonical benefits; competing mappings of one canonical/version pair remain unresolved. |
| `canonical` | `null` for an unestablished relationship, or `{id, evidence}` for an explicitly evidenced runtime relationship. `r04-*` catalog coordinates remain citations, not canonical runtime IDs. A shared name never establishes this relationship. |
| `source` | `{id, edition, status, publicationDate, citation}`. Status is explicitly `core`, `official-errata`, `optional-playtest`, `supplement`, `custom` or `synthetic`. A path containing “Errata” never supplies status. Dates retain known precision (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`); unknown is explicitly `null`. |
| `generationEligibility` | Explicit `eligible`, `excluded` or `unclassified` declaration. Only `eligible` can resolve attribution. This is not rule-version/content approval, an acquisition permission or a new scope filter. Future production mappings need actual accepted Generations 1–8 evidence under [SCOPE.md](SCOPE.md). |

Full rules and prerequisites live in the selected/owned Item, not the metadata. Citations and optional-source chronology do not merge, supersede or supply missing fields to that Item. The accepted [full04 handoff](validation/2026-10-30-full04-acceptance.md) supplies source evidence and specific unresolved obligations; it does not provide automatically approved runtime mappings.

## Read interfaces

- `lookupSelectedRuleVersion(item, {versions})` returns attribution status/issues, exact document/owned/source identities, a detached copy of the stored selection, mapped version/source/canonical metadata when resolved, and the owned raw prerequisites. Missing/ambiguous mappings, conflicting types/selection IDs, malformed metadata and noneligible scope declarations return `unresolved` with no selected-version fallback. `canonical: null` can coexist with known source/version attribution; it cannot support a guessed nonstacking group.
- `lookupEffectiveRule(item, {versions, mechanicChoices})` adds a detached snapshot of the **complete owned `system`**, without overlaying source or other-version data. This preserves custom descriptions, prerequisite text, rule elements, uses, costs and conditions. Attribution resolution does not certify that custom/owned fields equal a printed source, approve them or authorize automation. Unknown mappings still return the exact saved snapshot for preservation/manual inspection.
- `lookupMechanicChoice(id, choices)` returns an explicit string choice for that independent mechanic ID, or `standard` when no own property exists. Empty/invalid explicit values return `unresolved`; they are not silently reset. Choice values are preferences, not verified mechanics. This batch defines no supported-mechanic catalog, presets or adapters for existing Boolean/enum settings.

Identity uses the accepted modern-first `_stats.compendiumSource`/legacy `flags.core.sourceId` accessor. An actual compendium Document uses its own UUID rather than historical export provenance. A plain owned snapshot with source provenance uses that source without falling back to a convenient old stamp or another same-name record. A vanished transient provenance stamp remains an unknown mapping; no identity is reconstructed from text.

An existing `flags.ptu.selectedVersion` string or object is never rewritten. If present, its explicit ID must agree with the exact supplied mapping. A label-only flag cannot establish version identity. Renaming a display label does not change an established ID. With no stored flag, an exact supplied document mapping can establish attribution without writing a flag. No arbitrary raw `_id` is converted into a pack UUID.

The returned `selectedVersion` object is compatible with the accepted `diagnosePrerequisites({actor, item, selectedVersion, references})` interface. Pass the selected Item and its exact raw prerequisites. The focused test exercises this composition; production actor/item views and NPC selectors remain on their accepted interfaces. Do not bypass current ownership/security, acquisition/scope checks, genuine choices or effect-use predicates using a read result.

## Read-only replacement preview

`previewRuleVersionReplacement({actor, current, candidate, versions, mechanicChoices = {}, references = {}} = {})` is the sole export from [rule-version-preview.js](../src/util/rule-version-preview.js). Supply plain serialized snapshots with explicit Item UUIDs and consistent local IDs, and the existing explicit metadata mappings. There is no live-document adapter, UUID query, permission check or Item lookup. Callable/accessor/cyclic/nonserialized inputs are reported without calling their interfaces. This contract covers serialized data, not arbitrary JavaScript proxies.

The detached report contains:

| Field | Meaning and limits |
| --- | --- |
| `current`, `candidate` | Full detached snapshots, `snapshotAvailable`, shape/identity `inputIssues`, and separate lookup `attribution`. Complete flags, provenance, subchoices, costs and other custom data remain inspectable. Availability means serializable data was captured; it does not mean valid identity, approval or relationship. Unsafe/nonserialized input has no snapshot and an explicit issue; ordinary malformed serialized values remain visible. |
| `relationship` | `alternate-versions`, `same-selection`, `unrelated-benefits` or `unresolved`, with issues. Alternate/same selection requires exact explicit identity, resolved mappings, matching Item type and evidenced non-null canonical identity. Same-name labels never supply relationships. Same selection still has a system diff and complete snapshots, including custom differences. This describes only the supplied mapping claims. |
| `differences` | `complete` or `unavailable`, plus deterministic `system` changes with segment-array paths and separate `before`/`after` `{present, value}` sides. Missing has `present:false` and no value; null remains present null. Object keys sort ordinally for comparison, arrays are whole ordered values, and no scalar is coerced. Non-system fields remain in snapshots; they are not transfer decisions or updates. |
| `prerequisites` | Existing evaluator report for the candidate's own full raw requirements and resolved version, or explicit unknown attribution; existing formatter's separate `unmet` and `unknown` text lists. Invalid source-label objects keep the raw report and a `source-label-not-text` issue with unavailable formatting. Render strings as escaped text. Deficiencies never change the relationship into an acquisition veto. |
| `mechanics`, `contextIssues` | Independent declared preferences with the API's standard fallback context, plus explicit missing/invalid actor, mapping, reference or preference inputs. No preference selects/replaces a content version. Invalid actor/reference context is not queried or guessed; diagnostics use missing context and remain advisory/unverifiable where needed. |
| `outsidePreview` | Ownership/permissions, production source approval, acquisition scope, state-transfer policy, repeat/stacking policy and effect-use authorization remain unassessed. A relationship is not permission or approval. |

Nothing in the report is an executable update plan. There is no `canApply` or authorization result, no replacement payload, deduplication, dependency grant, rank increase, effect toggle, setting change, transaction or migration. Two repeated Poké Edges, ranked/repeated Features/Edges and their choices remain independent inputs. Source-backed production mappings and all application/live/permission/persistence/failure tests remain later explicitly assigned gates. Existing consumers and all accepted source/prerequisite/acquisition/preservation contracts are unchanged.

Owned-item diagnostic input accepts a direct dense Item-snapshot array or a serialized wrapper with a dense `contents` array. Unsupported shapes and null/scalar/array entries produce explicit actor context issues. Only collection membership becomes unavailable; a detached diagnostic projection retains valid skill/level facts. Empty arrays are known empty, whereas missing/null collections remain unknown. No supplied actor data changes. Array validation rejects non-index properties, including numeric4294967295 and larger keys; canonical indices end at4294967294. Legal but sparse maximum-index arrays receive a bounded first-hole diagnostic rather than a huge length scan. Ordered whole-array/presence comparisons remain unchanged for valid serialized data.

When raw diagnostic identity contains a non-null non-text `uuid`, `sourceId` or `id`, `prerequisites.formatted` is `null` and `prerequisites.issues` includes `identity-formatting-unavailable`. The preview never attempts string coercion or invents a replacement ID. It retains the complete raw diagnostic report and Item snapshots, candidate identity issues, selected-version attribution or explicit unknown, and independent actor facts. Ordinary missing identity still uses the existing formatter's unknown-attribution presentation; valid identities retain normal formatted diagnostics. This is a presentation boundary, not source approval, permission or an acquisition veto.
