## Limitations

- No general trainer/Pokémon sheet diagnostics, embedded report persistence, input-change/reload hooks or supported acquisition-route fixes are implemented here. P02 must integrate the pure interface and verify actual ownership/security/persistence routes, including Poké Edges and token contexts.
- Production variant creation/selection/replacement, effective rules, presets, nonstacking and new migrations remain 05. The two same-name synthetic fixtures demonstrate report separation only. Existing NPC Tagify catalog options still use inherited display values; this test supplies exact UUID widget values and does not certify production same-name variant browsing.
- Unresolved textual Item relationships remain unverifiable until an evidenced UUID mapping exists. No fuzzy-name fallback or guessed source meaning. Missing selected source UUIDs retain the inherited NPC resolution limitation; this batch does not certify safe source refresh/migration or general missing-source acquisition handling.
- Reports recompute from their inputs and are shown throughout the NPC draft. Closing the unsaved builder is not a draft persistence contract. Actual actor add/generation persistence, observers/non-owners, migrations/failure injection, imports, nested grants/choices, campaign upgrades, full scope exclusion, calculations and new gameplay are not retested by this batch.
- Diagnostic text uses the existing English panel presentation. No complete localization pass is claimed. The preserved core rank table/aliases are source-backed; custom syntax is conservative rather than a complete natural-language rules language.
- The Node NPC test controls Foundry IO; actual module/UI observations are separate. CI does not repeat proprietary Foundry UI interaction. Historical 183 parser and no-content NPC tests are not substituted for this selected-content evidence.
