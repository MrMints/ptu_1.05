## Reproductions and resulting behavior

- At `077711db`, two correctly matched mixed condition/ChoiceSet cancellations incremented an existing valued Condition from 1 to 2 despite cancelling. Ten saved-graph cases also failed preservation, including extra granted children. Initial counter fixtures containing digits did not exercise the intended existing-condition lookup; their apparent passes are retained and excluded from the correction proof.
- Intermediate `fff2c57f` deferred condition writes and preserved explicitly associated graphs, but four actual cases with an absent saved GrantItem flag still replayed a grant. Missing/blank/ambiguous rule-to-edge associations now refuse before creation. No flag is inferred from a label, slug or UUID.
- Passing a complete raw pair was insufficient for normal Duplicate/save and cross-actor drops: those routes retained the source Document but forwarded a single raw record. They now gather its complete reciprocal component from that Document's actual actor/world/compendium collection, require read access and preserve the selected Item's normal return interface. Additional linked Items are listed with source/destination and UUIDs in an explicit consent dialog, defaulting to No. Cancellation changes neither source nor destination.
- The first actual drop at intermediate `bce58b2f` exposed core `fromDropData` stamping provenance on the original Document in memory. Final saved-graph resolution returns the actual source without that mutation. Ordinary unlinked routes retain core behavior. The regression mock now reproduces core's stamp instead of omitting it.
- An unrelated `itemGrants: {custom:null}` could throw during incoming-link detection and block an ordinary unlinked copy. Incoming scans now ignore entries that establish no relationship; malformed metadata inside the selected component refuses unchanged with a structural message. No malformed/custom source is cleaned or rewritten.

Existing condition increments are staged until choices and Item creation succeed. Preparation alone writes no Condition. Core creation failure/veto applies no queued increment, and retry applies each requested increment once. This is not a general backend transaction or cross-document rollback guarantee.

Saved graph validation is independent of GrantItem callbacks: exact node IDs and reciprocal links must establish the component, including manual links with no GrantItem rule. Known saved rules are skipped by their original source index; genuine new rules still run. Independent copies remap only internal `itemGrants[*].id` and `grantedBy.id`, preserving raw rules, prerequisites, version/choice flags, custom fields and saved slugs. Saved Condition children retain their own value rather than merging into an existing same-slug counter. Repeated keep-ID restoration refuses collisions unchanged; legitimate ordinary copies remain repeatable.

The collector never searches other actors or uses provenance/name/coincident IDs to invent an origin. Missing, inaccessible, stale, inconsistent or unregistered source contexts refuse. Source identity/data and destination permission are rechecked after consent. Source-less incomplete raw data remains a refusal, rather than an unsupported label applied to normal Document copy/drop routes.
