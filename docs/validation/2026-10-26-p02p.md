`src/util/preservation.js` accepts complete typed or legacy compendium Item UUIDs and verifies the resolved Document's complete identity and type. Modern provenance wins, including when it cannot resolve; legacy metadata is not a fallback to another selection. Names, slugs, ID suffixes and same-name candidates never identify replacements. Known excluded source identities are refused. Missing/invalid/mismatched sources preserve the data and warn for manual review. Resolver exceptions propagate as failures rather than guessed success.

`PTUItem.refreshFromCompendium` uses this resolver and requires ordinary Item ownership. It retains original ID, name, custom image, provenance, flags, grants and selected-version data. Existing source-controlled text is now also preserved: refresh is a conservative missing-field operation, **not version replacement**. This workflow change is explicit in its notification and [TESTING.md](../TESTING.md). Future explicit replacement remains 05 work; no variant selector or forced conversion is introduced.

The shared runner now propagates transformation, persistence, embedded-document and free-form failures to the world completion boundary. Asynchronous Item migration and table writes are awaited. Failed phases do not report completion or advance the world stamp. `ensureSchemaVersion` updates its Document only after the cloned transformation completes. Schema records are not downgraded or rewritten on repeat. Older raw snapshots without a schema record are handled.

This is not a transaction across an entire world: earlier successful writes may remain when a later write fails. The old world stamp keeps the run retryable; the assigned transformations are preservation-oriented and repeat safe. No automatic rollback or reconstruction of previously lost data is claimed.
