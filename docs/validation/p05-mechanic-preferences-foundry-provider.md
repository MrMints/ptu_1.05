## Entry point and trusted boundary
`captureTrainerAdvancement(requestJson, authorize, observe)` takes exactly three arguments. The first must be a primitive JSON string; the latter two must be trusted finite synchronous functions. A new temporary GM-only pilot restriction is implemented here, not asserted as existing application enforcement. `callerRef` is an opaque exact correlation string, never a credential or a grant. The trusted authority port must establish real caller identity at a later host boundary; fixtures cannot prove native authorization. Authorization runs once before any registration or setting-content observation. Non-GM, unknown, failed, malformed or mismatched authorization stops with no observation call.

The request is closed: schemaVersion1, namespace ptu, key variant.trainerAdvancement, storageScope world, mechanicId ptu.trainer-advancement, mapping {original:standard}, and nonblank callerRef. No second key or alternate mapping is accepted. All tokens are exact, with no trimming/normalization. The authority reply is serialized JSON with schemaVersion1, matching callerRef, decision authorized, role gm and nonempty evidenceRef. Other replies fail closed.

Ports themselves are trusted executable dependencies. The adapter cannot prove purity, interrupt/cancel callbacks, detect every Proxy, make arbitrary inspection trap-free, prevent side effects or impose a callback wall-clock bound. A function Proxy can run a trap when called. An object/Promise/thenable reply is rejected without traversal or awaiting; its previously scheduled work cannot be cancelled by that rejection. The caller remains responsible for Promise rejection handling and external supervision. Parsed data cannot carry executable accessors. No native authority port or observation binding is installed in this package.

## Observation data and exact meanings
The one observation reply is a closed serialized record containing schemaVersion, namespace/key/storageScope, registration, presence, loadedSource, decoded, effective, overrideEvidence and consistency. All five ancillary fields use one of:
- {availability:available, value, evidenceRef}, requiring a nonblank reference.
- {availability:unavailable, reason, evidenceRef}, where reason is not-observed/incomplete/unreadable and reference is null or nonblank.

Registration must describe exactly String/world/default original, the five original/data-revamp/short-track/ptr-update/long-track choices in the pinned order, requiresReload true and config false. Unsupported declarations remain visible but unmapped. The observed registered default is preserved separately from source and effective values; no default is applied.

Presence is present/not-loaded/unknown with evidenceRef. Not-loaded means no loaded member, not database absence. The adapter never sends absent to the generic capture interface, so missing loaded membership cannot trigger standard fallback. Present-null stays distinct from missing membership. loadedSource is the already migrated/cleaned/shimmed model source value, not disk-raw. Its exact string is preserved and independently strictly decoded. decoded is the port's separate decoded observation; mismatch blocks mapping. effective is the prepared/cast observation; change versus decoded is reported separately as changed-observed, never repaired. False, zero, null, custom objects and other valid JSON evidence are preserved even though they cannot map to this String original choice. Invalid/unsupported source representations remain retained where the outer reply shape is valid.

A mapping needs explicit available overrideEvidence {status:none-reported}; this is a trusted port report, not proof that no runtime override exists. Any unknown or supplied different override evidence remains retained and blocks mapping. consistency requires no-change-detected, equal nonblank before/after tokens and evidenceRef. That is only a detected-change filter. Matching tokens, no await, object freezing and matching reads do not prove atomicity, completeness, or exclusion of cross-client/ABA changes. Every result says atomicity not-established.

Only decoded/effective original with all above gates maps to standard. The other four modes, unknown/custom/blank/null, unsupported declarations, missing source and inconsistent evidence remain unmapped. Physical evidence is never rewritten. Mapping and citation are independent output fields. The accepted capture utility is called directly with its full unchanged validator closure and selected one-mechanic declaration, no substitute stub. Unmapped results pass unknown evidence into it. The result retains sourceApproval not-assessed; declared core source metadata is not an authorization seal.
