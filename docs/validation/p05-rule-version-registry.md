## Identity and preservation contract

Two records for the approved pair produce four aliases, **not four mappings**. Duplicate canonical/version tuples are rejected; distinct canonical benefits sharing a version token are valid. Maps/Sets and tuple keys avoid prototype-name lookup hazards. Names, slugs, translated labels and old export pointers never establish equivalence.

Lookup still uses the unchanged modern-first `getDocumentSourceId` accessor and actual-pack UUID precedence. `identity.uuid`, `identity.sourceId` and `identity.mappingUuid` retain their original values. Successful canonical matching is separately reported as `registryMatch:{status:"matched",canonicalUuid}`. Unknown/foreign/malformed matching, invalid registries and conflicts remain unresolved. Excluded/unclassified rows may be structurally valid registry data, but cannot resolve attribution. Type and stored-selection conflicts remain explicit after a successful identity match.

Unknown nonempty modern provenance cannot use a convenient legacy source. Missing/null/empty modern values retain the existing explicit legacy accessor fallback. A nontext modern source blocks optional owned attribution; actual-pack UUID precedence still wins over historical or malformed provenance. This uncertainty guard applies only to the new optional route; exact-mode metadata/date validation and defaults remain compatible.

Preview compares validated canonical match UUIDs when supplied, so equivalent typed/legacy views of one version produce `same-selection`; core/May produce `alternate-versions`. Both preserve full original snapshots and system differences, including custom differences within `same-selection`. There is no update/transfer payload, default-driven owned replacement, prerequisite grant, rank change or permission/stacking decision. Descriptors are checked before cloning registry data; getters, toJSON/live interfaces, custom prototypes, sparse arrays, symbols, cycles and nonfinite values are rejected. Derived aliases are revalidated at consumption, preventing a forged alias table or post-construction duplicate from redirecting lookup. All results are detached; registry/input mutation does not rewrite supplied mappings or snapshots. The metadata validator remains the existing authority: its supporting constants, date logic and function body are LF-byte-identical to the accepted base.
