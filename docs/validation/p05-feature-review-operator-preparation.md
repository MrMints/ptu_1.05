### Collector and storage evidence

[captureStoppedStoreEvidence](../../tools/collect-feature-review-evidence.mjs) is inert until explicitly called. It requires a bridge constructed by `createFeatureReviewOperator`; a request object containing claimed operating facts cannot substitute for that bridge. Native mode rejects synthetic readers, OS adapters and clocks. Synthetic work is confined to a distinct ignored `.cache` batch.

Each baseline, conversion-before, conversion-after and closure stage has separate source paths, source pins, start/copy/finish times, process observations, collector hash, reader binding and output hashes. Stages do not claim to be contemporaneous. The collector verifies containment and ancestors, rejects links/unexpected objects, requires a fresh empty output stage and disjoint source/copy trees, and verifies privacy before sensitive writes. It creates an untouched byte copy, verifies it against the source manifest, then creates a separate working copy. Only the working copy may be opened through a database API. Source and untouched-copy bytes, file pins, reader/collector bindings and stopped state are rechecked before accepting output. Failures retain private copies/provenance and produce a generic failure record without echoing reader or decoder messages.

Copies use exclusive opaque-byte writes into destination directories whose inherited restrictions are verified before writing. Source ACLs are not copied. Provenance distinguishes expected core/system pins from actually observed source/copy bindings; it does not claim a running engine observation.

The reader resolves `classic-level` from pinned CLI `@foundryvtt/foundryvtt-cli` 3.0.5's dependency context, requires locked `classic-level` 3.0.0, and records the resolved entry/package/binding/native-addon hashes and actual Node/platform/ABI. It checks for an existing directory and `CURRENT` before opening with `createIfMissing:false`. It calls only raw iteration and close; no Foundry wrapper, repair, compaction, migration, document model, defaults or update API is used. Normal database opening may write to the disposable working copy. The reader refuses arbitrary paths outside collector-registered working copies or self-generated compatibility-test batches.

Native collection also verifies fourteen static Foundry 13.351 source bindings: the LevelDB wrapper, server document/embedded-field implementation and eleven concrete document hierarchies. These sources were inspected as text, never imported. The map distinguishes Cards/Card, PlaylistSound/AmbientSound and singleton ActorDelta records; it does not admit the later SceneLevel hierarchy. Every raw key/value receives a byte binding. Parent ID arrays and singleton IDs are joined only to their actual stored child records, preserving absence, order, IDs and all unlisted values. Missing, duplicate, orphaned, unknown or competing inline/separate representations stop collection. No child is silently dropped or defaulted.

Conversion envelopes retain the accepted `captured-store-payloads` format. Every admitted database's primary/embedded/folder denominator is checked. The complete 15-store payload has 7,198 primary, 2,790 embedded and 197 folder records: 10,185 total. Conversion-after reads the preceding capture with its private provenance/output/untouched-copy bindings and runs the unchanged `joinAdmittedConversionCaptures` full audit. An origin label or matching aggregate total is insufficient.

World stages enumerate all eleven protected collections plus settings, Users and fog. Unknown world-store entries, missing stores, nonempty fog or otherwise unrepresentable content stop collection. Required assembled documents contain only actual stored records. The full raw ledger is retained privately. Baseline and closure reuse `admittedBaselineErrors`, `admittedClosureErrors` and `admittedSystemManifest`. Prior/restored system manifests are measured from explicit contained directories, not supplied manifest claims. Raw setting records remain intact; a stored JSON setting value is decoded separately only to derive the compendium-configuration commitment.

User value buffers are hashed without UTF-8 or JSON decoding. Only raw keys establish their opaque record IDs. Separate, fresh normal-UI observations supply explicit id/name/role/ownership/permissions projections, with their own source/session/time and exact ID denominator. Extra fields, stale/future observations and contradictory IDs are refused; historical projections are not substituted. Native world stages hash and privately preserve only the exact options/license files as opaque bytes. They are never decoded or displayed. Complete records, raw ledgers, User/security observations, configuration/license bytes, plans and provenance stay outside served `Data`, Git and release artifacts. No permissions are changed to make collection work.

### Host checks and private bridge

[feature-review-operator](../../tools/feature-review-operator.mjs) checks contained paths, exact file pins, owner/SYSTEM inheritance, stopped/running process state, packet/segment bytes, baseline commitments, macro absence and relevant original archive/backup/conversion replay. `saveCapturedProof` emits the unchanged checker's raw envelope from a verified capture. `savePrivateControllerSegment` uses the protected merge, retains exact segment bytes and appends raw segment/checkpoint/case proofs without erasing previous evidence. The returned private plan must still be saved and replayed before acknowledgement.

Before each action, `verifyBaselineReadiness` rereads the measured baseline capture, verifies its retained untouched world-copy bytes, compares the actual fresh prior-system backup manifest with the baseline, rehashes the fresh backup-manifest file and checks both current opaque configuration bytes and their retained private copies. Changed fresh backups refuse action preparation. This host-side measurement supplements the original pinned archive/backup replay; it is not a readiness boolean or a claim of restored-world acceptance.

The process query applies the CIM provider filter for node.exe, electron.exe and Foundry%.exe before selecting command-line information. Output contains only target PIDs/names and unreadable relevant candidates. Port 30001 is queried directly; only the explicit no-match condition establishes absence. Other errors remain unknown. Stopped collection requires no matching process/listener/lock. Running actions require the exact owned PID, target listener and lock. The bridge launches/stops no server and changes no permissions or settings.

Supported usage, coordinator ownership, allowed hours, normal authorized access and applicable action-specific managed approval remain trusted-executor observations. Each needs its source, observation time and operating boundary, recorded privately. The bridge also calculates the Indianapolis weekday blackout itself. A callback returning caller-written JSON is not authenticated external evidence; the executor must obtain the actual tool/UI/review results. No authentication service or cryptographic claim is introduced.

**Execution-context boundary:** `observeHostState` starts PowerShell in its caller's context. Prior operating preflight established CIM access denied in the restricted command environment and success for a separately reviewed narrow process/port query. That query-only exception does not cover running a collector/operator command that also reads or writes private files. Ordinary-context host checks may refuse. A later different boundary-crossing command requires its own applicable authorization and managed review, disclosing the exact action, source/output paths and reason. Do not reuse stale snapshots, feed a JSON result as authority, switch to Full access, change permissions, use a broader query or silently move the whole collector outside the restricted environment. No actual host/world collection was attempted here.

### Browser verifier and action protocol

[createExecutionVerifier](../../tools/feature-review-execution-verifier.mjs) returns stable `verifyExecution(context)`, `armAction(witness)` and `disarm()` functions. Native verification rereads the actual global browser game/session: exact world/core/system/schema, socket/navigation session, principal/account set, permissions and disabled-module facts. It rejects supplied native browser/clock adapters. Successful verification returns `undefined`; refusal throws.

After completing actual host/operator checks, the trusted executor arms one logical action with a fresh nonce, exact public packet/anchor/digest, batch/session/principal, private operator-record hash and private merge acknowledgement. Leases last at most 60 seconds and expire sooner at an operating boundary. Future/stale observations, backward or divergent clocks, overlap, reused nonces, changed facts, unexpected operations and missing/wrong acknowledgements fail. The public packet and commitments contain no private baseline or accumulated GM history. They enforce consistency with a trusted observation; they do not authenticate OS state, usage or backups in the browser.

The explicit nested-guard bounds are exported as `ACTION_GUARDS`. Setup requires setup → bootstrap-macro → exact private-macro-absence verification; grants allows seven named grant checks; begin/finish require their two guards; checkpoint requires its snapshot guard before export; cleanup permits only its bounded normal/failed-abort/snapshot guards. A sealed reload permits open followed by the exact prior-segment acknowledgement. A refresh binds the next privately acknowledged packet using the same callback, then subsequent actions use that packet. The controller's retained pack Document references are not replaced or reconstructed.

`disarm()` belongs in the executor's `finally` after the single awaited action. It checks completion time and required guard observations. An overlong or incomplete action cannot receive a successful completion receipt. Expiry cannot cancel an already dispatched Foundry request; uncertainty requires STOP and separately checked, already-authorized safe handling. No automatic lease renewal, exceptional cleanup authority or silent failure reset exists. The first verifier failure reference persists; a fresh safe-action witness must acknowledge it, and the protected controller's own first-failure/lifecycle limits still apply.

The frozen controller does not invoke the callback for `capture-dom` or `close`. For those two actions the trusted executor must call `verifyExecution` with the exact current context immediately before the action, await completion and disarm afterward. Do not claim the callback alone intercepts those UI paths or asynchronous work after its last guard. Normal Foundry permissions remain unchanged.

Before bootstrap, `verifyPrivateMacroAbsence` reads the actual private baseline, verifies its byte hash and accepted schema, and compares the exact new macro ID against its complete preexisting macro IDs. It produces the exact identity-bound receipt used by setup. An absent/ack boolean is refused. Receipt hashes are consistency bindings, not external authentication.
